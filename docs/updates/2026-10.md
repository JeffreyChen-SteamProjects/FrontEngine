## U-20261030-03 · 2026-10-30 · Build the executable on every CPU core by default · #done #packaging #build

- **What**: `exe/build_exe.py --jobs` used to take only a positive cap. Without it, the job count was left to Nuitka. `resolve_jobs` now always passes an explicit count, and the build prints it.
  - No `--jobs`, or `--jobs auto`, compiles on every CPU core.
  - A positive number still caps the jobs to save compiler memory.
  - A negative number leaves that many cores free, for example `-2` on 8 cores gives 6 jobs.
  - `0`, non-numbers, and negatives that would leave no core are rejected before anything compiles. An unknown core count falls back to one job.
- **Tests**: `test_executable_build.py` covers the default, `auto`, caps, spare cores, the rejected values and the unknown core count.
