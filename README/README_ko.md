**무엇이든 화면 위에 — 또는 화면 아래에 놓으세요.**

FrontEngine은 데스크톱 오버레이 앱입니다. 동영상, 이미지, GIF, 웹 페이지, 텍스트,
파티클, 사운드, 그리고 애니메이션 펫을 다른 모든 창 위에 올려놓거나(클릭 통과되므로
아래에 있는 것도 그대로 작동합니다), 라이브 배경화면처럼 창 뒤에 배치할 수 있습니다.
그 주변에는 화면 자체를 위한 도구 모음이 있습니다. 눈 편안함 필터, 프레젠테이션 주석,
측정과 캡처, 집중 마스크, 데스크톱 위젯이 그것입니다.

[Steam에서 이 프로젝트 후원하기](https://store.steampowered.com/app/2793470/FrontEngine/)
 · [문서](https://frontengine.readthedocs.io/en/latest/)

## 설치

Python **3.10+**. Windows 10/11이 주요 대상이며, macOS와 Linux에서도 앱이
실행됩니다. 플랫폼 차이는 [플랫폼 지원](#platform-support)에 나열되어 있습니다.

```bash
pip install frontengine

frontengine                    # or: python -m frontengine
frontengine --preset "Work"    # apply a saved preset on launch
```

사전 빌드된 Windows 바이너리는
[Releases 페이지](https://github.com/JeffreyChen-SteamProjects/FrontEngine/releases)에
있으며, Steam 빌드는 Workshop 지원을 포함한 동일한 애플리케이션을 제공합니다.

> **빠져나오기.** 오버레이는 FrontEngine 자체 창을 포함해 화면 전체를 덮을 수
> 있으므로, 마우스 없이도 쓸 수 있는 두 가지 탈출구가 있습니다.
> `Ctrl+Shift+F12`는 모든 오버레이를 닫고, **F12는 어디서든 애플리케이션을 즉시
> 종료합니다**(Windows 전용 — *Help → How to force close* 참조).

## 화면에 올리는 것

사이드바는 페이지를 용도별로 묶습니다. 이 절은 그 순서를 따릅니다.

### 화면에 (On screen)

미디어 오버레이. 각각 자신의 모니터를 선택하거나(모든 모니터에 걸칠 수도 있음),
드래그한 위치를 기억하며, 자체 불투명도를 가집니다.

- **동영상** — 볼륨, 재생 속도, 반복 기능 포함.
- **이미지** — 한 장의 사진, 슬라이드쇼로서의 폴더, 또는 **레퍼런스 보드**: 하나의
  캔버스에 여러 이미지를 올리고 각각 드래그할 수 있으며, 보드 전체를 확대·이동할 수
  있습니다.
- **웹** — URL 또는 로컬 HTML 파일, 선택적으로 상호작용 가능. **대시보드 모드**는
  URL 목록을 순환하므로, 벽면 디스플레이가 단축키나 타이머로 페이지를 넘길 수
  있습니다.
- **GIF / WebP** — 조절 가능한 속도의 애니메이션.
- **텍스트** — 글꼴, 색상, 외곽선, 정렬, 마퀴 기능이 있으며, 고정된 문자열 또는
  **라이브 소스**(시계, 날짜, 카운트다운, 스톱워치, 시스템 부하, 날씨)를 표시합니다.
  라이브 소스는 `{field}` 템플릿을 사용하며, 페이지에는 각 소스가 제공하는 필드가
  나열됩니다.
- **사운드** — 음악 재생과 저지연 WAV 효과음.
- **씬** — 위의 여러 가지를 하나의 구성으로 합칩니다. 저장하고 공유할 수 있는 JSON
  문서로 기술됩니다.
- **파티클** — OpenGL 파티클 효과.

### 데스크톱

**데스크톱 펫** — 바탕화면에 사는 애니메이션 스프라이트.

- **스프라이트** — 하나의 GIF/WebP/PNG, 또는 파일 이름이 상태에 매핑되는 *펫 팩*
  폴더: `walk`, `idle`, `sleep`, `climb`, `fall`, `drag`(없는 상태는 `walk`로
  대체됩니다). 선택적 `pet.json`은 크기, 속도, 그리고 등반·대화·창에 앉기 가능
  여부를 설정합니다.
- **행동** — 중력을 받으며 바닥을 걷거나(던지면 튕깁니다), 자유롭게 돌아다니거나,
  커서를 쫓습니다. 바닥 펫은 화면 가장자리를 오르고 다른 창의 위쪽 가장자리에 섭니다.
- **삶** — 기분, 포만감, 그리고 실행 간에 유지되는 애정도. 레벨이 오르면 성장하고,
  말풍선으로 이야기하며, 자리를 비운 사이 낮잠을 자고, 배터리가 부족하면 경고합니다.
- **상호작용** — 드래그하고, 오른쪽 클릭으로 복제 / 먹이 주기 / 알림 설정을 하며,
  **파일을 그 위에 떨어뜨리세요**: 이미지나 펫 팩은 새로운 모습이 되고, 그 밖의
  것은 먹힙니다. 무엇을 먹느냐가 중요합니다 — 압축 파일은 성찬이고, 음악은 배를
  채우기보다 기분을 더 북돋우며, 문서는 소박한 식사이고, 바이너리는 씹기 너무
  어렵습니다.
- **술래잡기** — 화면에 둘 이상의 펫이 있을 때 *서로 술래잡기하기*를 체크하면 하나가
  "술래"가 됩니다: 가장 가까운 이웃을 향해 걸어가고 나머지는 반대로 달아나며,
  누군가를 잡으면 술래를 넘깁니다.
- **소리에 반응** — 펫이 스피커 출력에 맞춰, 또는 **마이크**에 맞춰 고동치므로 말할
  때 움직입니다. 둘 다 출력 *미터*만 읽습니다 — 오디오가 아니라 숫자입니다. 피크는
  RMS 윈도우와 빠른 어택/느린 디케이 엔벨로프로 부드럽게 처리되어, 깜빡이는 대신
  숨쉬듯 고동칩니다. 모니터가 여러 개일 때 각 펫은 자기 화면에 맞는 오디오 엔드포인트를
  따릅니다.
- **집중 타이머** — 같은 페이지의 뽀모도로로, 펫이 알려줍니다: 집중이 끝날 때와
  휴식이 끝날 때를 말해줍니다.
- **채팅** — `ANTHROPIC_API_KEY`가 설정되어 있으면 펫이 Claude를 통해 대답할 수
  있습니다. 활성화하지 않는 한 꺼져 있습니다. [기기에서 나가는 것](#what-leaves-the-machine)을
  참조하세요.

**배경화면** — 이미지와 애니메이션 폴더를 모든 창 *아래에서* 재생합니다. 각 모니터는
자체 타이머로 자기 폴더를 가리키며, 섞거나 재귀적으로 읽을 수 있고, 스피커 레벨에
맞춰 고동칠 수 있습니다. 두 번째 폴더는 조용한 시간대에 대신 나설 수 있습니다.

**위젯** — 바탕화면에 놓이는 네 가지:

- **오디오 스펙트럼** — 막대 또는 링 형태, 로그 간격 대역, 빠른 어택/느린 디케이
  팔로워로 부드럽게 처리되며, 아래로 흘러내리는 피크 마커가 있습니다.
- **재생 중** — 선택적 `winsdk` 바인딩이 설치되어 있으면 Windows의 미디어 컨트롤에서
  가져온 현재 트랙; 그렇지 않으면 실제로 소리를 내고 있는 앱의 이름.
- **시스템 모니터** — CPU, 메모리, 디스크, 배터리, 네트워크 처리량을 작은
  스파크라인으로; 원하는 선을 체크하세요. 평균은 멈춤을 숨기지만 선은 그렇지
  않습니다. 숨긴 선도 계속 기록하므로, 다시 켜면 그동안 무슨 일이 있었는지
  보여줍니다.
- **스티키 노트** — 모든 창 위의 편집 가능한 카드로, 세션 간에 텍스트, 색상, 위치를
  유지합니다.

### 작업 (Work)

**집중** — 화면이 작업과 경쟁할 때를 위한 두 가지 오버레이. *배경 창 어둡게*는 작업
중인 창을 제외한 모든 것을 조절 가능한 세기로 어둡게 합니다. *방해 요소 가리기*는
화면의 일부를 가립니다: 작업 표시줄, 알림 모서리, 가장자리, 또는 전체. 둘 다 클릭을
통과시키므로 가려진 것도 그대로 작동합니다 — 다만 시선을 끄는 일이 멈출 뿐입니다.

**화면 케어** — 화면 앞에서 긴 시간을 보낼 때를 위해:

- **색상 필터** — 따뜻한 색부터 앰버, 로즈, 회색까지 일곱 가지 색조를 조절 가능한
  세기로.
- **읽기 자** — 페이지를 어둡게 하고 커서를 따라가는 밝은 띠를 남깁니다.
- **휴식 알림** — 20-20-20 규칙으로, 간격이 되면 휴식 오버레이를 띄웁니다.
- **색각 시뮬레이션** — Machado 외(2009) 모델을 사용해 적색맹, 녹색맹, 청색맹,
  전색맹을 조절 가능한 정도로. 다른 오버레이와 달리 이것은 불투명한데, 다른 사람이
  보는 것을 보여주려면 화면에 색조를 입히는 것이 아니라 다시 그려야 하기 때문입니다.

**프레젠테이션** — 데모, 수업, 녹화를 위해:

- **주석** — 펜, 형광펜, 지우개로 화면 위에 그리며, 실행 취소와 지우기 기능이
  있습니다.
- **커서 효과** — 포인터 주위의 링, 클릭 시 파문, 그리고 나머지를 어둡게 하는
  스포트라이트.
- **키 입력 표시** — 방금 누른 키와 클릭한 마우스 버튼을 보여주어 시청자가 따라올 수
  있게 하며, 몇 초 후에 사라집니다. 패널이 놓일 위치와 텍스트 크기를 고르고, 마우스
  클릭만 따로 끌 수 있습니다.
- **돋보기** — 커서 주변 영역의 확대된 뷰.
- **화이트보드** — 무한 캔버스: 드래그로 이동, 스크롤로 확대, 그린 것을 저장.
  선은 캔버스 좌표에 존재하므로, 이동하고 확대해도 제자리에 남습니다.
- **정지** — 모니터의 현재 프레임을 고정해 정지 이미지 뒤에서 계속 작업할 수
  있습니다. `Ctrl+Shift+F7`이 해제하는데, 정지된 이미지가 그 역할을 할 버튼을 덮기
  때문에 중요합니다.

**도구** — 측정, 캡처, 창 처리:

- **색상 선택기 / 픽셀 자 / 각도기** — 클릭으로 샘플링하거나 측정합니다. 결과는
  `#rrggbb`, `rgb(...)`, `hsl(...)` 또는 CSS 사용자 지정 속성 형태로 바로
  클립보드에 들어갑니다.
- **영역 캡처** — 영역을 드래그하세요. 클립보드에 들어가고, 파일로 저장하거나, 위에
  떠 있는 확대 가능한 사본으로 **고정**할 수 있습니다.
- **영역 녹화** — 영역을 애니메이션 GIF로 녹화하며, 리액션 영상 느낌을 위해 카메라를
  모서리에 합성합니다. 모든 프레임을 메모리에 담기 때문에 길이와 프레임 수 모두로
  제한됩니다.
- **카메라** — 원, 둥근 상자, 사각형 형태의 웹캠으로, 로컬에서만 표시되고 절대
  녹화되지 않습니다. 캡처 카드를 포함한 모든 비디오 입력이 작동하며, 카드는 보통 앱이
  이미 실행 중일 때 꽂으므로 장치 목록은 재시작 없이 새로 고쳐집니다.
- **가상 카메라** — 오버레이까지 포함한 영역을, Zoom, Teams, Discord가 비디오
  소스로 선택할 수 있는 웹캠으로 보냅니다. 선택적 `pyvirtualcam` 패키지와 가상 카메라
  드라이버(OBS가 하나 설치합니다)가 필요합니다. 둘 중 하나라도 없으면, 버튼이 조용히
  실패하는 대신 그 사실을 알립니다.
- **텍스트 읽기** — 영역을 드래그해 그 안의 텍스트를 복사하거나, 번역하거나, 그에 대해
  질문합니다. 이 기능은 선택 영역을 기기 밖으로 보냅니다.
  [기기에서 나가는 것](#what-leaves-the-machine)을 참조하세요.
- **창 고정** — 다른 프로그램의 창을 위에 유지하거나 흐리게 하면서, 그것을 참고해
  작업합니다. 스태킹과 불투명도만 건드리며, 창 내용은 절대 건드리지 않습니다.
- **창 복제** — 다른 창의 작지만 항상 위에 뜨는 라이브 사본으로, 렌더링이나 채팅이
  묻혀 있는 동안에도 지켜볼 수 있습니다.
- **창 레이아웃** — 모든 창이 놓인 위치를 저장하고 나중에 되돌립니다. 창은 제목으로
  매칭되며, 화면에 없는 창은 추측하지 않고 건너뜁니다.

## 모든 것을 한 번에 제어하기

**컨트롤 센터** 페이지는 어느 탭에서 열었든 상관없이, 모든 페이지의 모든 오버레이에
닿습니다: 숨기기, 보이기, 닫기, 음소거, 잠금, 위치 초기화, 불투명도 단계 조절, 그리고
각 오버레이의 새로 고침 속도를 제한하고 렌더링 해상도를 낮추는 **품질 등급**(고급 /
균형 / 절약) 적용. 또한 OBS용 크로마키 배경, *캡처에서 숨기기* 토글, 로그 패널,
그리고 **이 데스크톱에 고정** 기능도 갖추고 있습니다 — 가상 데스크톱을 전환하면
오버레이가 비켜서고 돌아오면 다시 나타납니다. 고정을 해제하면 치워두었던 것을 모두
되돌립니다.

기본 전역 단축키, 모두 **Settings → Hotkeys**에서 재설정 가능:

| Shortcut | Action |
| --- | --- |
| `Ctrl+Shift+F12` | 모든 오버레이 닫기 |
| `Ctrl+Shift+F11` / `F10` | 모든 오버레이 숨기기 / 보이기 |
| `Ctrl+Shift+F9` | 모두 음소거 |
| `Ctrl+Shift+↑` / `↓` | 불투명도 올리기 / 내리기 |
| `Ctrl+Shift+L` | 잠금 또는 잠금 해제 (클릭 통과 vs 드래그 가능) |
| `Ctrl+Shift+→` | 다음 대시보드 페이지 |
| `Ctrl+Shift+F8` | 단축키 시트를 화면에 표시 |
| `Ctrl+Shift+F7` | 화면 정지 / 정지 해제 |
| `Ctrl+Shift+F6` / `F5` / `F4` | 미디어 재생/일시정지, 다음 및 이전 트랙 |
| `Ctrl+Shift+F3` | 포그라운드 창을 다음 모니터로 이동 |
| `F12` | 즉시 종료 (Windows) |

미디어 트랜스포트는 시스템 미디어 키를 보내므로, 그것을 수신하는 모든 플레이어에
닿습니다. 창을 옮길 때는 Windows 자체의 `Win+Shift+Arrow`처럼 화면을 가로질러
붙이는 대신 비율을 유지합니다.

원격 제어가 구동하는 것은 동일한 동작이며 — 그 이상은 아닙니다:

- **당신의 휴대폰** (Settings → Remote control) — FrontEngine이 로컬 네트워크에 작은
  페이지를 제공합니다. 휴대폰에서 링크를 열면 버튼이 그 동작들을 구동합니다.
- **MIDI 컨트롤러** — *Learn*을 누르고, 노브나 패드를 움직여 바인딩하세요. Windows에
  내장된 winmm을 사용하므로 추가 패키지가 필요 없습니다. 노브는 올라가는 도중에
  반복적으로가 아니라 맨 위에 도달했을 때 한 번 발동하며, 패드를 놓는 것은 두 번째
  누름으로 세지 않습니다.

## 프리셋과 자동화

**프리셋**은 모든 페이지의 설정을 한 번에 담습니다. **Presets** 메뉴에서 저장,
불러오기, 삭제, 내보내기, 가져오기를 하고, 실행 시 하나를 적용하거나, 이전 세션을
자동으로 복원할 수 있습니다. 프리셋은 **패키지**로 내보낼 수 있습니다 — 참조하는
미디어를 담은 zip이므로 — 그 파일이 없는 기기에서도 열립니다.

그런 다음 스스로 결정하는 것들, 모두 **Settings** 메뉴에 있습니다. 스마트 일시정지만
처음부터 켜져 있고, 나머지는 켜기 전까지 꺼져 있습니다.

| | |
| --- | --- |
| **규칙** | *"이 조건들이 성립하면 이것을 하라."* 요일, 시간대, 그리고 어느 애플리케이션이 포커스를 가졌는지를 조합한 뒤, 프리셋을 적용하거나, 오버레이를 숨기기/보이기/닫기 하거나, 품질을 설정합니다. 빈 조건은 "아무거나"를 뜻하며, 규칙은 조건이 성립하는 동안 반복적으로가 아니라 성립하기 **시작할 때 한 번** 실행됩니다. 이곳이 조건이 조합되는 유일한 곳이며, 아래의 각 행은 단일 종류만 압니다. |
| **스마트 일시정지** | 전체 화면 앱이 실행되는 동안, 기기가 배터리로 작동하는 동안, 또는 지정한 앱이 포커스를 가진 동안 오버레이를 물러서게 합니다. *(전체 화면 규칙에 한해 기본으로 켜짐.)* |
| **앱 프로필** | 지정한 앱으로 전환할 때 프리셋을 적용합니다. |
| **프리셋 예약** | 선택한 요일의 정해진 시간에 프리셋을 적용합니다. |
| **테마 예약** | 시계에 맞춰 낮 테마와 밤 테마를 전환합니다. |
| **사이니지 모드** | 메인 창을 치워둔 채 프리셋 목록을 타이머로 순환합니다. 디스플레이로 계속 켜둔 기기를 위한 것입니다. |
| **화면 보호기** | 유휴 임계값을 넘으면 선택한 동영상 / 이미지 / GIF / 파티클 / 웹 페이지를 띄우고, 돌아오면 내립니다. |
| **알림** | N분마다, 또는 하루에 한 번 정해진 시간에, 스스로 닫히는 토스트로 표시됩니다. |
| **깨어 있기** | 오버레이가 떠 있는 동안 디스플레이가 절전되지 않게 합니다. |
| **시스템과 함께 시작** | 로그인 시 실행합니다. |
| **화면 시간** | 어느 앱이 얼마나 오래 포커스를 가졌는지를, 일일 세부 내역과 7일 요약과 함께. 키보드에서 떨어져 있는 동안 일시정지되고, 최대 60일을 보관하며, 지우기는 파일 자체를 삭제합니다. |
| **클립보드 기록** | 복사한 것을 검색하고 자주 쓰는 문구를 고정하세요. 클립보드는 흔히 비밀번호를 담으므로, "세션 간 유지"를 따로 체크하지 않는 한 **메모리에만** 보관됩니다. |

## 언어

일곱 가지: English, 繁體中文, 简体中文, Deutsch, Русский, Français, Italiano.

**Language** 메뉴에서 하나를 고르면 인터페이스가 **즉시** 바뀝니다 — 재시작 없이.
열어두었던 것은 그대로 열려 있습니다: 오버레이는 계속 실행되고, 모든 페이지의 설정은
있던 그대로 남습니다. Steam 설치판에서는 첫 실행 시 Steam 클라이언트 자체의 언어를
따릅니다.

## 개인정보 및 플랫폼 참고 사항

### 기기에서 나가는 것

FrontEngine의 모든 것은 이 목록에 있지 않는 한 로컬입니다. 예외는 네 가지이며, 모두
옵트인입니다:

| Feature | Where it goes | Guard |
| --- | --- | --- |
| **텍스트 읽기** (Tools) | 선택한 영역이 Anthropic의 API로 전송됩니다 | 첫 전송 전에 한 번 묻고 답을 기억합니다. 동의는 결과 창에서 철회할 수 있습니다. 환경에서 읽고 설정 파일에는 절대 기록하지 않는 당신 자신의 `ANTHROPIC_API_KEY`를 사용합니다. 둘 다 없으면 아무것도 전송되지 않습니다. |
| **펫 채팅** | 당신의 메시지가 Anthropic의 API로 갑니다 | 같은 키, 같은 규칙. 기본으로 꺼져 있습니다. |
| **날씨** (텍스트 소스) | 좌표가 Open-Meteo로 갑니다 | 키 없음, 계정 없음, 식별 데이터 없음. 위치로 입력한 것만. |
| **휴대폰 원격** | 로컬 네트워크에 페이지를 제공합니다 | 기본으로 꺼져 있습니다. 링크는 시작할 때마다 재생성되는 토큰을 담으므로 오래된 링크는 작동을 멈추며, 페이지는 고정된 동작 목록만 요청할 수 있습니다. 평문 HTTP입니다: 같은 네트워크의 다른 사람이 토큰을 읽고 같은 버튼을 누를 수 있습니다 — 그 버튼들이 하는 일을 고려하면 침해라기보다 성가심이지만, 신뢰하지 않는 네트워크에서는 꺼두세요. |

오디오 기능은 출력 **미터**만 읽습니다 — 하나의 숫자 — 단, 주파수를 계산하려면 실제
샘플이 필요해 시스템 출력 스트림을 캡처하는 스펙트럼은 예외입니다. 그 샘플은
메모리에서 분석되고, 디스크에 기록되거나 어디로도 전송되지 않으며, 스펙트럼을 멈추는
순간 캡처도 멈춥니다.

**플러그인**은 Python이며 FrontEngine과 동일한 권한으로 실행됩니다 — 샌드박스화할 수
없습니다. 로딩은 기본으로 꺼져 있고(Settings → Load plugins), 모든 로드가 기록되며,
망가진 플러그인 하나는 앱을 멈추는 대신 건너뜁니다. 신뢰하는 플러그인만 설치하세요.

### 화면 공유 개인정보

당신의 오버레이는 당신을 위한 것이지, 공유하는 상대를 위한 것이 아닙니다. **Settings →
Screen-sharing privacy**에서 FrontEngine은 회의 앱이 열려 있는 동안 오버레이를 캡처
밖으로 빼낼 수 있습니다:

- **당신 자신의 화면에는 그대로 남습니다.** 캡처된 사본만 비어 있습니다 — 이것은
  Windows의 `WDA_EXCLUDEFROMCAPTURE`를 사용하며, 회의 앱과 녹화기가 존중하는
  OS 수준의 플래그입니다.
- **마스크는 예외입니다.** 방해 요소 마스크는 무언가를 가리기 위해 존재하므로,
  캡처에서 의도적으로 계속 보입니다.
- **트리거는 당신의 목록입니다.** Windows에는 신뢰할 만한 "내가 캡처되고 있는가" API가
  없으므로, 당신이 지정한 창 제목을 감시합니다 — 이는 브라우저 탭에서 열린 회의도
  잡아내는데, 그 경우 실행 파일은 그냥 브라우저이기 때문입니다.

컨트롤 센터에도 수동 *캡처에서 숨기기* 버튼이 있습니다.

> 이것은 개인정보이지 보안이 아닙니다: 일반적인 캡처 경로를 무력화하며, 책상에 앉은
> 사람에게서는 아무것도 숨기지 않습니다.

### 플랫폼 지원

여기에 나열되지 않은 모든 것은 세 플랫폼 모두에서 작동합니다.

## 개발

```bash
pip install -r dev_requirements.txt
pip install -e .

python -m pytest tests/ -q          # the whole suite, headless (Qt offscreen)
```

정적 검사는 pyflakes(`dev_requirements.txt`에 포함)를 사용하며, 깨끗한 트리는 아무것도
출력하지 않습니다:

```bash
python -m pyflakes frontengine/ exe/ tests/
```

테스트 스위트는 전적으로 오프스크린으로 실행되며 디스플레이, 사운드 카드, 카메라가
필요 없습니다. 외부 세계에 닿는 것은 무엇이든 주입 가능한 소스를 취해 가짜로 테스트할
수 있습니다.

- **아키텍처** — [`architecture_explore.md`](../architecture_explore.md)는 모든
  모듈, 레이어링, 오버레이 계약, 확장점을 지도로 보여줍니다. 페이지나 오버레이를
  추가하기 전에 읽으세요: 여러 가지(컨트롤 센터 레지스트리, 일곱 개 언어 사전, 일곱 개
  문서 트리)를 함께 업데이트해야 하며, 테스트가 이를 강제합니다.
- **기여** — [`CONTRIBUTING.md`](../CONTRIBUTING.md)를 참조하세요. 풀 리퀘스트당 기능
  하나, 모든 CI 검사 통과.
- **Windows 실행 파일 빌드** — `python exe/build_exe.py`
  (Nuitka; 단일 파일을 원하면 `--onefile` 추가).
- **문서** — `docs/`의 Sphinx 소스로,
  [Read the Docs](https://frontengine.readthedocs.io/en/latest/)에 일곱 가지 언어
  모두로 게시됩니다.

## 지속적 통합과 릴리스

작업은 `feature → dev → main`으로 흐르며, 마지막 단계만 게시합니다:

```
feat/xyz  ──PR──►  dev  ──PR──►  main
                    │              │
              CI, no release   CI + release
```

| Workflow | Trigger | Purpose |
| --- | --- | --- |
| `CI` (`ci.yml`) | `main` 또는 `dev`로의 Push / PR, 수동 디스패치, 또는 `Nightly`가 호출 | 컴파일하고, 유닛 테스트를 실행한 뒤, *그 체크아웃*에서 wheel을 빌드해 설치하고 앱을 시작 — Python 3.10 / 3.11 / 3.12, Windows에서 |
| `Nightly` (`nightly.yml`) | 매일 cron, 수동 디스패치 | `CI`를 호출합니다. 스케줄이 일부러 여기 있습니다: GitHub은 cron을 담은 워크플로를 약 60일간 비활성 상태면 비활성화하는데, 그렇지 않으면 그것이 PR 검사까지 함께 무너뜨리기 때문입니다 |
| `Release` (`release.yml`) | **`dev`에서 온** 풀 리퀘스트가 `main`에 병합되거나, 수동 디스패치 | 버전을 올리고, `[skip ci]`와 함께 되커밋하며, `stable.toml` → `pyproject.toml`을 바꾸고, sdist + wheel을 빌드해 PyPI에 `frontengine`으로 업로드하고, `v<version>` 태그가 붙은 GitHub 릴리스를 만들며, `dev`를 fast-forward 합니다 |

게시는 **`dev`가 `main`에 병합될 때만** 일어납니다. 기능은 버전을 만들지 않고 `dev`에
안착하며, 릴리스는 의도적인 `dev → main` 풀 리퀘스트입니다. 실수로 `main`을 겨냥한
기능 PR도 병합은 되지만 게시하지는 않습니다 — 실패의 방향은 원치 않는 릴리스가 아니라
누락된 릴리스입니다.

패치 세그먼트는 자동으로 올라갑니다. 마이너 또는 메이저 릴리스는 *Actions → Release →
Run workflow*를 실행해 세그먼트를 고르세요. 그 경로는 실패한 게시를 새 병합 없이 다시
실행하기도 합니다.

버전은 두 파일에 존재합니다: `pyproject.toml`은 dev 패키지(`frontengine_dev`)이고
`stable.toml`은 게시되는 것(`frontengine`)입니다.

저장소 시크릿 하나가 필요합니다: `PYPI_API_TOKEN`, `frontengine` 프로젝트로 범위가
한정된 PyPI 토큰. 워크플로는 twine 사용자명으로 `__token__`을 사용하므로, 토큰 자체만
저장하면 됩니다.
