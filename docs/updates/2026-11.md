## U-20261101-01 · 2026-11-01 · Pet home domain layer: world, simulation, economy and saves · #done #pets #game

- **What**: the Qt-free core of the pet life and work game (`progress.md` #25, with the domain halves of #26–#28). `frontengine/utils/pet_game/` holds the catalog, deterministic RNG, ledger, zones and furniture, routines, residents, work orders, behaviour lifecycle, the fixed-step simulation, the `World` command surface and versioned snapshots; `frontengine/user_setting/pet_game_save.py` writes them. No page, overlay or service uses it yet.
  - Time: 200 ms steps (5 Hz) from accumulated effective milliseconds, never paint frames; one game day is 60 effective minutes; offline time is never simulated.
  - Behaviour order: safety → direct command → urgent need (energy ≤ 15, fullness ≤ 25) → routine block → assigned work → free activity. Every interruption goes through `cancel_activity()`, which releases the interaction point and pauses work with its progress.
  - Economy: integer coins and stacks, all-or-nothing transactions with IDs; a settlement is `<task>:u<unit>` and a repeated ID is a no-op. Basic bed, table and desk are essential (never sold, never bought); nap and snack need no furniture, so no home can get stuck.
  - Saves: `frontengine.pet-home` v1, one file per mode, 2 MiB cap, reload check before temp + fsync + replace, last good file kept as `.bak`. Corrupt or newer files are never overwritten (`restore_backup()`, `set_aside()`); content that is not installed stays as dormant records and comes back when reinstalled.
- **Decision**: cancelling a started unit returns its reserved inputs in full instead of keeping a work-in-progress item. Nothing is produced, so nothing is duplicated, and nothing is lost. Revisit when multi-stage recipes exist.
- **Decision**: a task stores a station only when the player picks one. Automatically chosen desks are runtime-only; storing them let a paused order keep a desk forever, and two of six residents never worked in the three-day run.
- **Result / numbers**: 66 new tests. First loop with the starter kit: 3+ letters paid, sleep and a plant purchase inside 15 effective minutes. Six residents sharing one bed, one table, two desks, a toy box and an armchair for three game days (54,000 steps): every resident worked, slept and ate; no reservation held by a resident doing something else. 1.18 s for those steps, about 22 µs per step (budget 5 ms). Full suite and pyflakes clean.
- **Files**: `frontengine/utils/pet_game/*.py`, `frontengine/user_setting/pet_game_save.py`, `tests/unit_test/test_pet_game_economy.py`, `test_pet_game_life.py`, `test_pet_game_save.py`, `architecture.md`, `architecture_explore.md`.

## U-20261101-02 · 2026-11-01 · Pet home service: one clock, identity leases, background saves · #done #pets #game

- **What**: `frontengine/show/pet_game/home_service.py` (`HomeService`) owns one home for the UI that comes next (`progress.md` #25).
  - Time: one 200 ms timer for the whole home; monotonic elapsed time; gaps over 5 s (sleep, hibernation, a stalled loop, clock jumps) are dropped. Named pause reasons stack, and nothing runs until `start()`.
  - Identity: each resident takes the ordinary `PetProfileSession` lease and never starts that session's care timer, so the world is the only clock and the same pet cannot also run as a desktop pet (`active_elsewhere`). A resident whose pet is live elsewhere at load is `away` (runtime only) until `retry_leases()`.
  - Saving: commands and settle/place/arrive events debounce a save; the snapshot is encoded and reload-checked on the GUI thread and written by a single worker, latest wins, with the result delivered through a queued signal. Failure emits `save_failed`, keeps memory and retries in 5 s. After the home file is written, care values are mirrored to the pet profiles through their sessions; the home file is authoritative if that second write fails. `HomeSaveStore` gained `encode()` / `write_encoded()` for this split.
  - Shutdown: stop time, cancel every activity without rewards (work is saved paused with its progress), save synchronously, release leases. Returns False and keeps everything if the save fails.
- **Result / numbers**: 10 tests (`tests/unit_test/test_pet_game_service.py`): running/paused time and dropped gaps, single time source with profile write-back, double adoption refused, away-then-retry, failed saves, shutdown without partial pay, release, worker-thread writes coalescing two saves into the latest and failures reported on the GUI thread.
- **Files**: `frontengine/show/pet_game/__init__.py`, `home_service.py`, `frontengine/user_setting/pet_game_save.py`, `tests/unit_test/test_pet_game_service.py`, `architecture_explore.md`.
- **Open items**: hooking hide-all, lock and meeting mode to the pause reasons, and showing save failures, stay in `progress.md` #25.
