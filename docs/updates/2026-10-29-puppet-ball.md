# Puppet 球玩具

Puppet 選單新增投球；寵物管理頁的互動清單對 Sprite 與 Puppet 都提供投球，並作用於選取的身分。球、光點與呼叫仍由 `PuppetTargetController` 管理單一目標，開始其中一個會釋放前一個標記。

`BallToy` 改為接受明確的移動擁有者與返回容差，Sprite 預設路徑不變。Puppet 由目標控制器提供實際工作區範圍與導引，每個 tick 先推進球，再以既有的浮點位移移動一次視窗；寵物本身沒有假的 `motion` 屬性。球的飛行、彈跳、拖動重投、右鍵收起與完成獎勵只有一份實作。另建 Puppet 專用球元件的方案被否決，因為每個範圍、逾時與獎勵變更都得改兩處。

兩個與 Sprite 不同之處已處理：小型 Puppet 能回到貼著工作區邊角的原中心（返回容差 2 邏輯像素），每次重投都重新計時，不會被上一輪的逾時提早取消。完成往返加 1 好感，沿用 30 秒活躍時間冷卻；照顧、手動拖曳、模式切換與隱藏取消時不發獎勵。

測試涵蓋 16×16 與 320×480 兩種尺寸在四個工作區角落的往返、拖動暫停與重投逾時、三種目標互換與忙碌拒絕保留照顧、選單與管理頁入口、Sprite 管理頁投球作用於選取身分，以及既有呼叫中斷測試加入 ball 參數。球、光點、呼叫、翻譯與文件共 143 項檢查通過，pyflakes 無輸出。七棵 Sphinx 文件樹與 README 十種語言同步更新。

原生 Windows GL 用 `tests/integration/puppet_call_native.py <輸出目錄> ball` 驗證，`.audit/pet-implementation/native-ball-2026-10-29/result.json` 為 passed：觀測到 chase、flight、return 三個階段，回到起點 (5663, 200)，完成 ball_return 只加 1 好感，影像逐像素恢復，計時器停止，手動 expression 保留，測試視窗未取得前景。此證據使用螢幕外合成工作區與合成模型；正式撿球動畫、真實螢幕／混合 DPI 與產品開窗焦點仍需另驗收。
