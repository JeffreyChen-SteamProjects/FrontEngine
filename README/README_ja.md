**画面の一番上に、あるいは一番下に、どんなものでも配置できます。**

FrontEngine はデスクトップ用のオーバーレイアプリです。動画、画像、GIF、ウェブ
ページ、テキスト、パーティクル、サウンド、そしてアニメーションするペットを、
ほかのすべてのウィンドウの上に置いたり（クリックスルーなので、下にあるものは
そのまま使えます）、ライブ壁紙としてそれらの背後に置いたりできます。その周りに
は、画面そのもののためのツール群があります。目に優しいフィルター、プレゼン用の
注釈、計測とキャプチャ、集中用のマスク、そしてデスクトップウィジェットです。

 · [デモを見る](https://youtu.be/fewogcb3b8Y)

## インストール

Python 3.11 以降をサポートしますが、3.14.0 から 3.14.4 は対象外です。Python 3.14 を使う場合は 3.14.5 以降を選んでください。主な対象は Windows 10/11 です。macOS と Linux でもアプリは
動きますが、プラットフォームごとの違いは [プラットフォーム対応](#プラットフォーム対応)
に一覧があります。

Windows の Python 3.14.4 で Qt のネイティブクラッシュを再現したため、それ以前の 3.14 パッチも予防的に除外しています。既存の仮想環境は互換性のあるインタープリターで作り直し、ソースからの実行にもそのインタープリターを使ってください。対象外のバージョンを組み込んだ EXE は、互換性のあるインタープリターで再ビルドする必要があります。FrontEngine パッケージの更新では Python は更新されません。

```bash
pip install frontengine

frontengine                    # or: python -m frontengine
frontengine --preset "Work"    # apply a saved preset on launch
```

ビルド済みの Windows バイナリは
[Releases ページ](https://github.com/JeffreyChen-SteamProjects/FrontEngine/releases)
にあり、Steam ビルドは同じアプリケーションを Workshop サポート付きで配布します。

> **抜け出すには。** オーバーレイは FrontEngine 自身のウィンドウを含め、画面
> 全体を覆うことがあります。そこで、マウスを必要としない脱出口が二つあります。
> `Ctrl+Shift+F12` はすべてのオーバーレイを閉じ、**F12 はどこからでもアプリケー
> ションをそのまま終了します**（Windows；macOS はアクセシビリティ権限が必要。*ヘルプ → 強制終了の方法* を参照）。

## 画面に置けるもの

サイドバーは各ページを用途ごとにまとめています。このセクションはそれに沿って
います。

サイドバーの各ページにはアイコンが付き、上部の検索欄（Ctrl+K）でコマンドを開けます。メニューバーのヘルプとドキュメントのメニューは、その名前どおりの表記になりました。幅の広いウィンドウでは設定ページのカードが中央の一列に収まり、ペットのおうちとシーンエディターは全幅を使います。

### ホーム

**ペットのおうち** — 最初のページ。保存したペットが小さなおうちに引っ越し、自分で暮らしながら働いてコインを稼ぎます。

- *おうちを作る* とベッド、ダイニングテーブル、書き物机と 10 コインがもらえます。押すまでは何も作られず何も始まりません。他のツールはおうちがなくても使えます。おうちを作る前に、保存済みのペットが *一緒に引っ越すペット* にすべてチェック付きで並びます。残したいペットはチェックを外してください。チェックしたペットはそのままの姿で引っ越します（同じ ID・名前・親密度・気分・満腹・元気・見た目・ワードローブ）。何も複製・リセットされず、外したペットは後から住人タブで引っ越せます。そのときも初期の持ち物は二度配られません。おうちの一年は 7 ゲーム日ずつの四季（春・夏・秋・冬）でできていて、ステータス行と、全体表示の空に舞う花びら・落ち葉・雪で分かります（*動きを減らす* では止まったまま）。冬の雨は雪になります。季節ごとにその季節の目標（花を育てる、遊ぶ、ハーブを収穫する、くつろぐ）があり、報酬は一度だけです。逃した季節は翌年またやってきます。 保存済みのペットがいないときは、*おうちを作る* で最初のペットも一緒に来て、選択された状態になります。
- 保存したペットを *引っ越す* か、*新しいペット* を作ります。同じペットがおうちとデスクトップに同時にいることはありません。体力・満腹・機嫌・なつき度は引き継がれ、引っ越して出るときにプロフィールへ戻ります。
- *模様替え* で収納の家具を床に置きます。赤いプレビューが置けない理由（おうちの外、すでに何かある、入口をふさぐ）を表示します。Esc で終了。*しまう* と家具が収納に戻り、そこでの仕事は進み具合を保ったまま一時停止します。模様替え中は家具をドラッグして動かすか、選んで ← ／ → で 1 マスずつ動かせます。*元に戻す* と *やり直す*（Ctrl+Z ／ Ctrl+Y）はすべての配置の変更に使えます。*配置をコピー* は配置コード（家具と位置だけで、ペットやコインなど個人的なものは含みません）をクリップボードに入れ、*配置を貼り付け* で読み込みます。4 つの既成の配置（*はじめのおうち*、*くつろぎコーナー*、*工房*、*ガーデンアトリエ*）は、*配置を適用* で購入して並べる前に、足りない物と値段を表示します。前の配置は *元に戻す* 一回で戻ります。*床にエリアを描く* で床の区間を *くらし*、*仕事*、*くつろぎ*、*食事* と名付けられます（名前を消すこともできます）。ペットは今している事に合ったエリアの家具を優先しますが、ほかの家具が禁止されることはありません。2 台目のモニターがあれば、*その画面にエリアを追加* でそこに自分のデスクトップの帯を持つエリアができ、*このエリアをそこへ移す* で移動できます。ペットがエリアを移るのは *そのエリアへ移す* を使ったときだけです。モニターを外すと、そのエリアのペットは待機し、家具はその場に残ります（何も複製されません）。画面が戻れば続きから暮らします。*キャットタワー* と *クライミングウォール* は高い場所にあります。活発なペットは自分で跳び上がり、ほかのペットにはそばに *ペット用階段* が必要です。どちらもないと赤いプレビューに「だれも上がれません」と表示されます（作業台はいつも床の上です）。*入口の行き先* で 2 つのエリアの入口をつなぐと通り道になり、ペットは空き時間にときどき遊びに行き、寝る時間には自分のベッドへ帰ります。接続されていない画面へは行きません。*間取りを共有…* で、おうち全体の部屋と家具を JSON ファイルに保存できます（ペット・名前・コイン・目標・画面名など個人的なものは含みません）。*間取りを訪ねる…* はそのファイルを読み取り専用で開きます。部屋を見て回れますが、何も動かず、買われず、保存されず、ネットにもつながりません。間取りでないファイルは開けません。この FrontEngine にない家具は表示せず、名前を一覧にします。
- *仕事* は設定いりません。ペットは勤務時間になると、作業場所でできる仕事を自分の得意な仕事から自分で引き受け、リュックにある材料だけを使います。タブには、それぞれが何をしているかが作る物の絵と一緒に並び、どの仕事も取り消せます。完了した 1 単位はちょうど一度だけ支払われ、取り消した分は支払われません。最初の家具は自動で並び、*配置* は収納の家具を最初の空き場所に置きます（*模様替え* で床をクリックして場所も選べます）。*ショップ* で買った家具はそのままおうちに入り、終わった *はじめの目標* のごほうびと、品物がそろった依頼は自動で片づきます。ショップ、リュック、収納はどの家具や品物も絵で表示します。タイルの名前と価格は別々の行に表示され、タイルの大きさはフォントに合わせて変わり、長い名前もツールチップで全文を確認できます。*設定* タブに残るのは、デスクトップへの表示と動きを減らす設定だけです。作業台は右クリックメニューか家具タブから 2 回まで *アップグレード* できます（価格は家具とレベルで決まり、自由な模様替えでは無料）。同じ種類の作業台はレベルを共有するので、しまったり並べ替えたりしても失われず、1 レベルごとに 4 分の 1 速く働きます。空き時間のペットは働いているペットを手伝いに行くことがあり（手伝いは 2 匹まで、1 匹ごとに速さが 4 分の 1 上がります）、その仕事を少し覚えます。倉庫にその品が 20 個あると、自動の仕事はそれを作らなくなります。家具には今の様子が表示されます。使われている間は点、ペットが働いている間はその仕事の道具（✎ ❀ ⚒）、仕事が終わると数秒間 ✓ が出ます。*集中中はペットも一緒に働く* をオンにすると、ペットページの集中タイマーを始めたときに、手の空いているペットそれぞれに仕事のお願いが入ります（今していることは中断されず、報酬はいつもどおりで、入力内容を読んだり休憩をとがめたりはしません）。休憩やタイマーの停止では、おうちが入れたお願いだけが取り消されます。どの仕事にも、スキルレベル 4 のペットとレベル 4 のおうちで受けられる上級の仕事があります。*長編小説を書く*（120 コイン）、*花束を作る*（花 3 本で 30 の価値の花束）、*オルゴールを作る*（木材 3 つとおもちゃ 1 つで 80 の価値のオルゴール）です。
- *ショップ* で家具を買えます。売ると最大で半額が戻り、基本のベッド・テーブル・机は売買できません。おうちの家具は 45 種類あり、それぞれに用途か見た目の違いがあります（ペットクッションから二段ベッドまでのベッド、テーブル、仕事ごとに複数の作業場所、ソファ、ビーズクッション、ボールプール、ピアノ、ラグ、水槽など）。一部はおうちのレベルが上がると解放され、ショップに必要なレベルが表示されます。短編小説、花、スツールも同様です。*コレクション* タブには家具図鑑（すべての家具と入手方法）、ペットの作品、アルバムがあります。暮らしの予定が自動になったため、はじめの目標「予定を選ぶ」は「飾りを置く」に変わりました。古いセーブの状態は引き継がれます。家具パックを入れると、ショップとコレクションに家具が増えます。パックは `pet-home-packs`（設定タブの *パックフォルダーを開く*）の中のフォルダーで、`pack.json`（形式 `frontengine.home-pack` バージョン 1、フォルダー名と同じ固定 ID、名前、出典、ライセンス、最大 64 個の家具の ID・名前・種類・幅・固さ・使う位置・用途・求めるポーズ・値段・快適さ）と、家具ごとの `furniture/warm_home/<art>.png`（ほかのテーマは任意）、`thumbnail.png` を入れます。知らない項目、パックの外へ出るパスやリンク、PNG でない画像や 2 MB を超える画像、重複した ID、実行できるファイルのどれかがあると、パック全体を読み込まず、理由を設定タブに表示します。パックの中身が実行されることはありません。家具の ID は `<pack>__<id>` になり、パックを外してもセーブ内の家具は残り、戻せば元どおりです。 第 2 コレクションでフロアランプ、吊り下げ植物、衣装だんす、布団、こたつ、テレビ、暖炉、木馬、望遠鏡、シャワーが加わりました。
- パックはテーマも持ち込めます（名前、家具画像を借りる内蔵テーマ、床・昼の空・夜の空の色）。テーマは家具タブのテーマ一覧に加わり、テーマだけのパックでも構いません。パックがなくなったテーマを使っている家はそのテーマを保ち、パックが戻るまでは暖かい家の見た目になります。家具パック、テーマ、設計図は Steam Workshop にもそれぞれの種類として並びます。購読したパックとテーマは次に FrontEngine を起動したときに家に入り、購読した設計図は読み取り専用の訪問として開きます。設計図は必要なコンテンツパックを記しており、Workshop の一覧と訪問の両方で、入っていないものが示されます。
- ページはゲーム画面のような配置です。上におうちがあり、日付・時刻・天気・コインと *開始* ／ *一時停止* が一行に並び、その下に *住人*、*仕事*、*家具*、*ショップ*、*リュック*、*目標*、*受信箱*、*コレクション*、*設定* のタブがあるので、操作中もおうちが見えたままです。おうちがまだないときは、新しいおうちに付くベッド・テーブル・机が *おうちを作る* の横に表示されます。総覧の下には *デスクトップに戻る*、*リュック*、*目標* とズーム（− ／ + または Ctrl+ホイール）があり、*あなた待ち* リストにはおうちが自分では片づけられないこと（まだペットがいない、未読の通知、収納に残った家具、材料待ちの仕事、開けるお祝い、願い）が並び、行をクリックすると該当タブが開きます。模様替え中はデスクトップの帯に *模様替えを終える* が出ます（帯はキーボードを受け取らないため）。新しい FrontEngine で保存されたデータでは *最新の FrontEngine を入手* が表示されます。*自由配置* は、家具をすべて使えて費用もコインもない別のおうち（``pet-home-sandbox.json``）に切り替えます。そこでのことは運営中のおうちやそのコイン・目標、ペット自身の数値には届きません。行き来するときは先に保存し、ペットがしていたことはごほうびなしで終わります。
- 時間が進むのはおうちが動いている間（*開始* / *一時停止*）だけで、FrontEngine を閉じていた時間やスリープ中の時間は計算しません。おうちは設定の隣の `pet-home.json` に保存され、ひとつ前の正常なコピーは `pet-home.json.bak` に残ります。読めない保存データや新しいバージョンの保存データは上書きしません。ページからバックアップに戻すか、古いファイルを残して新しいおうちを始められます。 保存に失敗しても再試行で成功すると、その保存のエラー表示は消え、受信箱にはエラー履歴が残ります。 終了時に設定、ペットやおうちの状態、メモ、前回のセッション、使用履歴を保存できない場合、FrontEngine は開いたままとなり、問題を解決して再試行できます。それ以前に成功した書き込みや、キャンセルされた活動は元に戻りません。

仕事リストのアクセシビリティラベルは、画面の表示言語に合わせて更新されます。

仕事リストにキーボードフォーカスが移ると、仕事を選択する前でも枠線が強調表示されます。

各プロセスで実行できる FrontEngine の操作ウィンドウは一つです。そのバックグラウンド処理とウィンドウの終了が完了するまで設定フォルダーを保持し、別のプロセスは同じフォルダーを開けません。JEditor と PyBreeze は埋め込みウィンドウを再利用し、保存に失敗した場合や終了処理中はホストを開いたままにします。

狭いウィンドウでは、ホームの状態テキストを操作ボタンの上に表示し、ボタンは必要に応じて折り返します。GIF オーバーレイの終了後は、元のファイルを移動または削除できます。

ペットの生成、プレビュー、デスクトップペットとホームの住民の既定の衣装庫、ホームの画像は、ホストの作業ディレクトリが変わっても設定ページが保持するデータディレクトリを使用します。明示的に指定したペット素材ライブラリは維持されます。 ホームの写真、アルバム、ローカルコンテンツパックのフォルダーも同じデータディレクトリを使用します。 写真は保存に成功するとすぐにアルバムに表示されます。ホームが一時停止中でも同様です。

終了準備中および終了中はホームパネルの操作を受け付けず、設計図のファイル選択結果も使用前に再確認します。終了を取り消すと新しい操作を受け付けますが、拒否した操作は再実行しません。

ホーム作成後も、狭いウィンドウではショートカットや長いボタン・チェックボックスの説明が折り返されます。操作部品はパネルに合わせて縮小でき、ホームの描画領域は独自の横スクロールを維持します。 選択した家具の名前と案内は狭いパネルで折り返され、家具タブが他のホームタブを横に広げることを防ぎます。 ホームのタイトルとバックパック・コレクション内の家具数も、狭いパネルに合わせて折り返されます。

ホームの操作メッセージは言語変更に追従し、数量、ファイルパス、元のエラー内容を保持します。保存に成功すると対応する失敗通知を消し、新しい操作メッセージは残します。

ゲーム内の日付が変わると、生活イベントや報酬が発生していなくても、その日の依頼が画面に反映されます。

受信済みのイベントも言語切り替えに追従し、繰り返し回数、当時のペット名、報酬額を保持します。 家園を一時停止している間も、新しい通知やすべて既読にする操作が対応待ちリストにすぐ反映されます。

設定ページを個別に埋め込むホストは、lifetime= で明示的な DefaultSettingsLifetime を渡す必要があります。そのライフタイムを閉じる前にページを保存して停止し、finished シグナルを確認してからホストを終了してください。 [Runtime lifetime API](../docs/formats/runtime-lifetime.md)
- レイヤーキャラクター（内蔵の INKSIDE キャラクターや衣装だんすのキャラクター）を着たペットは、おうちの中でもその姿で現れます。移動中は歩き、机やひじ掛けいすでは座り、ベッドで眠り、テーブルで食べ、おもちゃ箱で遊び、あいさつし合い、歩く方向を向きます。住人の *衣装だんす…* でいつもの衣装だんすが開き、新しい衣装はすぐおうちに反映されます。キャラクターはバックグラウンドで読み込まれ、それまでの間は色付きのマーカーが表示されます。デスクトップに出したことのある画像ペット（GIF、画像、スプライトパック）と Puppet ペットは、おうちでも自分の姿で現れます。スプライトパックなら自前の歩き・待機・睡眠アニメーション、GIF なら自前のフレーム、Puppet なら自分のキャンバスから撮った静止画を使います。静止画が一枚だけのペットは、歩くときに弾み、遊ぶときに跳ね、眠るときに縮こまります。使える自分の姿がないペット（新しいペットや、画像が移動された場合）は、毎回同じ内蔵キャラクターの姿で現れます。ペット自身の見た目やデスクトップのペットは変わりません。服を着ておらず、標準のパーツと色のままの内蔵キャラクターには専用の手描きポーズがあります。ベッドで眠り、アームチェアに座り、食べ、遊び、机で書き、プランターに水をやり、作業台で槌を打ちます（座る・眠る・食べる・遊ぶはデスクトップでも見られます）。服を着たり色を変えたりすると、レイヤーアニメーションのまま持ち場に座ります。古いバージョンの内蔵キャラクターを着ているペットは、衣装と色を保ったまま自動で現行バージョンに移ります。
- おうちには四つの *モード* があります。*通常*、デスクトップの帯を静かにする *集中*（吹き出しやカードを出さない）、おうちを隠して一時停止しそれを表示する *会議*、ペットの暮らしの速さは変えずに帯を毎秒 15 フレームで描く *省電力* です。画面共有中は会議モードになります。*受信箱* は仕事の完了、欲求、出来事、問題を集め、同じ出来事は一行にまとめ、ポップアップやフォーカスの奪取はしません。ペットが自分で食事や昼寝をしたことは載りません。
- おうちには昼と夜と天気があります。総覧の空はゲームの時計に合わせて夜明けから夜へと変わり、晴れ・くもり・雨はゲーム内 6 時間ごとに、おうち自身から決まるので毎回同じです。天気は雰囲気だけで、何かを壊したり待たせたりはしません。三つのテーマ（*あたたかい家*、*みどりのアトリエ*、*夜のアトリエ*）は色だけを変え、配置は変えません。家具は Blender でモデリングした輪郭つきのカートゥーン画像で、テーマごとに色が変わります。名前は家具を選んでいるときと配置中だけ表示されます。雨の日、星空の夜、はじめての親友、仕事の上達、緑あふれる家、にぎやかな家、はじめての短編、豊作が出来事に加わり、全部で 12 種類になりました。*動きを減らす* をオンにするとペットが歩みの間をすべらず、雨も止まって見えます。すべての出来事はカードと出来事一覧にも文字で表示され、おうちは音を出しません。
- 環境音は *設定* タブでオンにするまでオフで、独自の音量があります。昼は鳥のさえずり、夜は虫の声、その天気なら雨音や冬の風。家が一時停止中、会議中、またはパソコンがロック中は鳴りません。デスクトップの帯では、夕方と夜に家具とペットが少し暗くなります。帯の空いた部分は透明のままなので、クリックは後ろのウィンドウに届きます。 雨や雪の日は、帯の上にも雨粒や雪が降ります。マウスもフォーカスも受け取らない専用のレイヤーに描かれ、集中モードと会議モードでは止まり、*動きを減らす* では静止します。
- *目標* はおうちとともに育ちます。暮らしの節目（三つの仕事を経験、住人が増える、家具が増える、仲良しの友達）でおうちのレベルが上がり、小さなごほうびが自動で受け取られる *はじめの目標* が 10 個（いつでも飛ばせて、あとから見返せます）、毎日 3 件の *依頼* は商品をコインで買い取り、連続ボーナスや見逃しペナルティはありません。ペットごとに、かなえ方が書かれた期限のない小さな願いがあり、誕生日、初めての手作り、友達との夕食といった出来事や、2 匹以上が一緒に暮らし三つの仕事をすべて経験したあとに一度だけのおうちのお祝いもあります。*写真を撮る* はおうちの絵だけを設定の隣の `pet-album` に保存し、デスクトップは写しません。リュックには家具コレクションの集まり具合が表示されます。
- ペットには快適さと仲間も必要です。ベッドやひじ掛けいす、飾りがおうちを快適にし、快適さが低いと機嫌が下がります。ペット同士であいさつし、一緒に食事や遊びを楽しんで仲良くなり、ときには最後の空席をめぐってちょっとけんかもします。ペットにはそれぞれ変わらない性格（働き者、遊び好き、物静か、社交的、または園芸・書き物・手作りが好き）があり、選ぶ行動に影響し、好きな仕事は少し早くこなします。どの性格でも何かに向かないということはありません。カードには性格、仲良しの友達、今の行動の残り時間が表示され、デスクトップでは短い吹き出しで、始めたこと・あいさつした相手・稼いだ額を伝えます。古い保存データは読み込み時に新しい欲求が補われ、このバージョンで保存したおうちは古い FrontEngine から保護されます。
- ペットは清潔でいるのも好きです。清潔さはゆっくり下がり（遊んでいると早く下がります）、汚れたペットはその場で毛づくろいするか、より早く済む浴槽で入浴します。ブラッシングも効果があり、浴槽のない家に汚れたペットがいると、家の下のリストが浴槽を勧めます。
- 仕事は三種類です。机で書き物、*プランター* で園芸（ハーブで食事が楽しくなり、花は売れます）、ショップで買った木材を使って *作業台* で手作り（おもちゃは売れ、スツールはそのまま収納に入ります）。仕事は見える段階（種まき、水やり、収穫…）で進み、材料が足りないときは始めずに待ちます。*リュック* にはおうちの持ち物と仕事用に取り置いた数が並び、商品を売れます。買値は必ず売値より高く、どんな仕事の連鎖でも物が元の物に戻ることはありません。
- おうちはデスクトップにも住んでいます。画面の下端、タスクバーの上に立つ透明な帯です。マウスを受け取るのはペット、家具、小さな ⌂ ボタンだけで、それ以外のピクセルは後ろのウィンドウへクリックを通し、帯がフォーカスを奪うこともありません。ペットをクリックするとカード、右クリックで指示、ドラッグで移動、家具を右クリックするとしまえます。*デスクトップにおうちを表示* でオフにでき、表示レイヤーでウィンドウの上か下かを選べます（既定は上）。すべて隠すとおうちは再表示まで一時停止し、コントロールセンターの画質設定で毎秒 60・30・15 フレームを選べます。おうちの時間の進み方は変わりません。⌂ の横の矢印でツールバーが開き、*模様替え*・*住人*・*仕事* と、コイン、最後にクリックしたペット、進行中の仕事が表示されます。⌂ メニューで帯の反対側へ移せ、開閉と位置は記憶されます。ペットの右クリックメニューは *ごはん*・*なでる*・*話す*（満腹・気分・つながりが少し上がります。種類ごとに 30 秒に 1 回まで、ほかで休んでいるペットには使えません）から始まり、*お願いする*（各コマンド）、*ワードローブ…*、*このペットの仕事…*、*全体表示で追う*（拡大した全体表示で見失わないようにします）と続きます。家具の右クリックメニューには用途と使用中のペットが表示され、*移動*（デスクトップ上でそのまま模様替え）と *しまう* があります。コンピューターをロックしたときも同じように一時停止し、ロックを解除するまでステータス行に表示されます。おうちのペットにファイルをドロップすると、ごはんをあげたことになります（同じく 30 秒に 1 回まで）。ファイルは開かれず、変更も削除もされず、素材やコインにもなりません。ペットのメニューには *毛づくろい* と *おもちゃで遊ぶ*（仕事・食事・睡眠中は不可）、*こっちにおいで*（右クリックした場所まで歩いてきて少し待ちます）、*鬼ごっこ*（いちばん近い手の空いたペットと。忙しいペットは巻き込まず、2 匹とも楽しみます）、*写真を撮る*（全体表示からそのペットを撮ってアルバムに保存）もあります。
- 帯は小さくも大きくもできます（75〜200 %、家具・ペット・高さがまとめて変わります）。ペットや家具の上で Ctrl + マウスホイール、⌂ → *大きさ*、または設定タブで選べ、選択は記憶されます。その大きさで画面より広い家は画面内にとどまり、最後にクリックしたペット（またはペットたち）が見えるように滑らかに動きます。帯のペットをダブルクリックすると、なでられます。
- 最初のメニュー **機能** に、すべてのツールが用途別にまとまっています（メディア、シーンと壁紙、ウィジェット、集中と目のケア、プレゼン、キャプチャ、ペット、自動化、コンテンツと Workshop、オーバーレイ管理、設定とヘルプ）。*機能を検索*（Ctrl+K）、*ピン留め*、*最近使った項目* もあります。各項目は以前と同じページを開き同じコマンドを実行するので、ショートカット、プリセット、ルール、スマホのリモコン、MIDI はそのまま動きます。プリセット・設定・言語・ヘルプのメニューもそのまま中に入っています。サイドバーのグループは見出しをクリックすると折りたたまれ、その状態が保存されます。トレイメニューには *ペットのおうちを開く* が加わりました。

仕事の一覧が空の場合は、住民の生活スケジュール、作業台、バックパックの材料を確認してください。未完了の仕事を選択すると、キャンセルできるようになります。

すべてのチュートリアル目標の報酬を受け取るか、目標をスキップすると、スキップボタンは非表示になります。目標の一覧は引き続き確認できます。

### 画面上

メディアオーバーレイ。それぞれがモニターを選び（あるいはすべてにまたがり）、
ドラッグした位置を覚え、独自の不透明度を持ちます。

オーバーレイは既定で FrontEngine のある画面に、確認なしで開きます。 ファイルを選ぶとすぐ表示され、ページにドロップしても同じです。ファイルなしで *開始* を押すと選択画面が開きます。テキストや URL の欄が空のときは警告ダイアログではなく欄そのものを示し、欄で Enter を押すと開始します。

- **動画** — 音量、再生速度、ループ付き。
- **画像** — 一枚の写真、スライドショーとしてのフォルダ、あるいは **リファレンス
  ボード**：一つのキャンバスに複数の画像を置き、それぞれをドラッグでき、ボード
  全体をズーム・パンできます。
- **ウェブ** — URL またはローカルの HTML ファイル。任意で操作可能にできます。
  **ダッシュボードモード**は URL のリストを順に切り替えるので、壁面ディスプレイ
  がホットキーやタイマーでページを巡回できます。
- **GIF / WebP** — 速度を調整できるアニメーション。
- **テキスト** — フォント、色、縁取り、揃え、マーキーを備え、固定の文字列か
  **ライブソース**のいずれかを表示します。時計、日付、カウントダウン、ストップ
  ウォッチ、システム負荷、天気です。ライブソースは `{field}` テンプレートを取り、
  ページにはそれぞれが提供するフィールドの一覧があります。
- **サウンド** — 音楽の再生と低遅延の WAV 効果音。
- **シーン** — 上記のいくつかを組み合わせて、保存・共有できる JSON ドキュメント
  で記述する一つの構成にします。
- **パーティクル** — OpenGL のパーティクルエフェクト。

### デスクトップ

**デスクトップペット** — デスクトップに住む、アニメーションするスプライト。

ページの最初は *あなたのペット* です。内蔵キャラクターをクリックすると、その姿のペットがすぐデスクトップに現れます。*自分の画像…* も選べます。その下にはデスクトップにいるペットが *ワードローブ*、*ペットを呼び戻す*、*しまう* と並び（ダブルクリックで呼び戻し）、ほかの設定はセクションを開くまで折りたたまれています。

- お世話では各個体の元気と遊び／仕事／休息モードを保存し、バージョン 1 の UUID と数値を引き継ぎます。スプライトのメニューに挨拶、なでる、毛づくろいを追加しました。時間制の動作は完了時のみ報酬があり、満腹なら食事を断り、繰り返しには待ち時間が必要です。お世話は活動時間で進み、非表示やオフライン中の時間は後から加算しません。Puppet は共通セッションと給餌ルールを使い、実際の反応はランタイムとモデルの対応状況によります。

- **スプライト** — 一つの GIF/WebP/PNG、あるいはファイル名が状態に対応する
  *ペットパック*フォルダ：`walk`、`idle`、`sleep`、`climb`、`fall`、`drag`
  （状態が欠けていれば `walk` にフォールバックします）。任意の `pet.json` で
  サイズ、速度、そして登る・話す・ウィンドウの上に座ることを許すかどうかを
  設定します。
- **振る舞い** — 重力に従って床を歩く（投げると跳ねます）、自由に歩き回る、
  あるいはカーソルを追いかける。床ペットは画面の端を登り、ほかのウィンドウの
  上端に立ちます。
- **ライフ** — 気分、満腹度、そして実行のあいだ持続する愛着レベル。レベルが
  上がると成長し、吹き出しで話し、あなたが離れているあいだは昼寝をし、バッテ
  リー残量の低下を警告します。
- **インタラクション** — ドラッグする、右クリックで複製 / 餌やり / リマインダー
  設定、そして **ファイルを落とす**：画像やペットパックは新しい見た目になり、
  それ以外は食べられます。何を食べるかが重要です。アーカイブはごちそう、音楽は
  満たすよりも元気づけ、ドキュメントはささやかな食事、バイナリは噛むには硬すぎ
  ます。
- **鬼ごっこ** — 画面上に二匹以上のペットがいるとき、*互いに鬼ごっこをする*に
  チェックを入れると一匹が「鬼」になります。鬼は最も近い相手に向かって歩き、
  ほかは逆方向に逃げ、誰かを捕まえると鬼が引き継がれます。
- **音に反応する** — ペットはスピーカーの出力に合わせて、あるいは**マイク**に
  合わせて脈打つので、あなたが話すと動きます。どちらも読むのは出力の *メーター*
  だけ、つまり音声ではなく数値です。ピークは RMS ウィンドウと、速いアタック /
  遅いディケイのエンベロープで滑らかにされるので、脈動はちらつかず呼吸します。
  複数のモニターがある場合、各ペットは自分の画面に対応するオーディオエンドポ
  イントに従います。
- **集中タイマー** — 同じページ上のポモドーロで、ペットが知らせます。集中が
  終わったときと休憩が終わったときを教えてくれます。
- **チャット** — `ANTHROPIC_API_KEY` が設定されていれば、ペットは Claude を
  通じてあなたに答えられます。有効にしない限りオフです。[マシンの外に出るもの](#マシンの外に出るもの)
  を参照。

**壁紙** — 画像とアニメーションのフォルダを、すべてのウィンドウの*背後*で
再生します。各モニターは独自のタイマーで独自のフォルダを指し、シャッフルまたは
再帰的に読み込み、スピーカーレベルに合わせて脈打つこともできます。二つ目の
フォルダが静かな時間帯に引き継ぐこともできます。

**ウィジェット** — デスクトップに置ける四つのもの：

- **オーディオスペクトラム** — バーまたはリング、対数間隔の帯域で、速いアタック
  / 遅いディケイのフォロワーで滑らかにされ、ゆっくり下がっていくピークマーカー
  付き。
- **再生中** — 任意の `winsdk` バインディングがインストールされていれば、Windows
  のメディアコントロールから現在のトラックを表示します。そうでなければ、実際に
  音を出しているアプリの名前を表示します。
- **システムモニター** — CPU、メモリ、ディスク、バッテリー、ネットワークの
  スループットを小さなスパークラインで表示します。表示したい線にチェックを
  入れてください。平均は失速を隠しますが、線は隠しません。隠した線も記録を
  続けるので、再び表示すると、そのあいだに何が起きたかがわかります。
- **付箋** — すべてのウィンドウの上に置ける編集可能なカードで、テキスト、色、
  位置をセッション間で保ちます。
  全体の描画バックエンドを切り替えても、付箋の文字は表示され、編集できます。

### 作業

**フォーカス** — 画面があなたの作業と競合するときのための二つのオーバーレイ。
*背景ウィンドウを暗くする*は、あなたが作業しているウィンドウ以外のすべてを、
調整可能な強さで陰にします。*気を散らすものを覆う*は画面の帯を覆い隠します。
タスクバー、通知の隅、端、あるいはそのすべてです。どちらもクリックを通すので、
覆われたものはそのまま使えます。ただ目を引くのをやめさせるだけです。

**画面ケア** — 画面に向かう長時間のセッションのために：

- **カラーフィルター** — 暖色からアンバー、ローズ、グレーまで七つの色合いを、
  調整可能な強さで。
- **リーディングルーラー** — ページを暗くし、カーソルに追従する明るい帯を
  残します。
- **休憩リマインダー** — 20-20-20 ルール。間隔が来ると休憩のオーバーレイを
  出します。
- **色覚シミュレーション** — Machado et al. (2009) のモデルを使い、第一色覚
  異常、第二色覚異常、第三色覚異常、全色盲を調整可能な重症度で。ほかのオーバー
  レイと違ってこれは不透明です。他人に見えているものを見せるということは、
  画面に色を重ねるのではなく塗り直すことだからです。

**プレゼン** — デモ、レッスン、録画のために：

- **注釈** — ペン、蛍光ペン、消しゴムで画面上に描画でき、取り消しとクリアが
  可能です。
- **カーソルエフェクト** — ポインターの周りのリング、クリック時の波紋、そして
  それ以外を暗くするスポットライト。
- **キーストローク表示** — 今押したものと、どのマウスボタンをクリックしたかを
  表示するので、視聴者が追えます。数秒で消えます。パネルの位置とテキストの
  大きさを選べ、マウスクリックだけをオフにできます。
- **拡大鏡** — カーソル周辺の領域を拡大表示します。
- **ホワイトボード** — 無限のキャンバス：ドラッグでパン、スクロールでズーム、
  描いたものを保存します。ストロークはキャンバス座標で存在するので、パンや
  ズームをしても本来あるべき場所に残ります。
- **フリーズ** — モニターの現在のフレームを固定し、静止画像の背後で作業を続け
  られるようにします。`Ctrl+Shift+F7` で解除します。これが重要なのは、固定
  された画像がそれを行うボタンを覆ってしまうからです。

**ツール** — 計測、キャプチャ、ウィンドウ操作：

- **カラーピッカー / ピクセル定規 / 分度器** — クリックしてサンプリングまたは
  計測します。結果は `#rrggbb`、`rgb(...)`、`hsl(...)`、または CSS カスタム
  プロパティとして、そのままクリップボードに入ります。
- **領域キャプチャ** — 領域をドラッグで切り出します。クリップボードに入り、
  ファイルに保存でき、あるいは浮動しズーム可能なコピーとして最前面に**ピン留め**
  できます。
- **領域を録画** — 録画：範囲を選択し、キャプチャ開始前に出力 GIF を選びます。キャンセルでは録画を開始しません。バックグラウンドでフレームを逐次書き込み、キューは3フレームと64 MiBを上限とします。大きすぎる単一フレームは拒否します。キューが満杯ならキャプチャを省略し、経過時間を再生時間に反映します。フレームレート、時間、フレーム数の上限とカメラの小窓は維持します。停止後は非同期で完了し、成功時のみ出力先をアトミックに置換します。キャンセルや書き込み失敗時は一時ファイルを削除し、既存ファイルを保護します。
- **カメラ** — ウェブカメラを円、角丸ボックス、または長方形で、ローカルに表示
  し、録画は一切しません。キャプチャカードを含め、あらゆる映像入力が使えます。
  カードはたいていアプリの実行中に接続されるので、デバイスリストは再起動なしで
  更新されます。
- **仮想カメラ** — 領域を、オーバーレイもすべて含めて、Zoom、Teams、Discord が
  映像ソースとして選べるウェブカメラとして送ります。任意の `pyvirtualcam`
  パッケージと仮想カメラドライバー（OBS が一つインストールします）が必要です。
  どちらかが欠けていると、ボタンは静かに失敗するのではなく、そう表示します。
- **テキストを読む** — 画面の文字：ツール → テキストを読むは最初にローカル OCR を使います。Windows は Windows.Media.Ocr、macOS は Vision、または実行ファイルと言語データをインストールした Tesseract を使用します。ローカル抽出はクラウドへの同意や ANTHROPIC_API_KEY を必要とせず、正常な空結果でもスクリーンショットを送信しません。翻訳と質問は、文字送信への個別の同意とキーがある場合のみ、認識済み文字を Anthropic に送ります。ローカル失敗後の画像フォールバックは、別の画像送信同意とキーを必要とします。結果にはバックエンドとエラーを表示し、同意も撤回できます。
- **ウィンドウをピン留め** — 別のプログラムのウィンドウを最前面に保つ、または
  それを見ながら作業するために薄くします。触れるのは重なり順と不透明度だけで、
  ウィンドウの内容には決して触れません。
- **ウィンドウの複製** — 別のウィンドウの小さな常時最前面のライブコピーなので、
  レンダリングやチャットが埋もれていても見ていられます。
- **ウィンドウレイアウト** — すべてのウィンドウがどこにあるかを保存し、後で
  戻します。ウィンドウはタイトルで照合され、画面にないものは推測されるのではなく
  スキップされます。

## すべてを一度に制御する

**コントロールセンター**ページは、どのタブが開いたかにかかわらず、すべての
ページ上のすべてのオーバーレイに手が届きます。隠す、表示する、閉じる、ミュート、
ロック、位置のリセット、不透明度の段階変更、そして各オーバーレイのリフレッシュ
レートに上限をかけレンダリング解像度を下げる **品質ティア**（高 / バランス /
省エネ）の適用です。さらに OBS 用のクロマキー背景、*キャプチャから隠す*トグル、
ログパネル、そして **このデスクトップにピン留め** も備えています。仮想デスク
トップを切り替えるとオーバーレイは脇に退き、戻ってくると戻ります。ピン留めを
解除すると、退けたものが戻ってきます。

デフォルトのグローバルホットキーはすべて **設定 → ホットキー** から再割り当て
できます：

| Shortcut | Action |
| --- | --- |
| `Ctrl+Shift+F12` | すべてのオーバーレイを閉じる |
| `Ctrl+Shift+F11` / `F10` | すべてのオーバーレイを隠す / 表示する |
| `Ctrl+Shift+F9` | すべてをミュート |
| `Ctrl+Shift+↑` / `↓` | 不透明度を上げる / 下げる |
| `Ctrl+Shift+L` | ロックまたはロック解除（クリックスルー対ドラッグ可能） |
| `Ctrl+Shift+→` | 次のダッシュボードページ |
| `Ctrl+Shift+F8` | ショートカット一覧を画面に表示 |
| `Ctrl+Shift+F7` | 画面をフリーズ / フリーズ解除 |
| `Ctrl+Shift+F6` / `F5` / `F4` | メディアの再生/一時停止、次と前のトラック |
| `Ctrl+Shift+F3` | 前面ウィンドウを次のモニターへ移動 |
| `F12` | 即座に終了（Windows / macOS*） |

メディアトランスポートはシステムのメディアキーを送るので、それを待ち受ける
あらゆるプレーヤーに届きます。ウィンドウの移動は、Windows 自身の
`Win+Shift+Arrow` のように画面をまたいでスナップさせるのではなく、比率を
保ちます。

同じアクション、そしてそれ以上のものは一切なし、これがリモートコントロールが
操作するものです：

- **あなたのスマホ**（設定 → リモートコントロール）— FrontEngine はローカル
  ネットワーク上に小さなページを提供します。スマホでリンクを開けば、ボタンが
  それらのアクションを操作します。
- **MIDI コントローラー** — Learn を押し、ノブやパッドを操作して割り当てます。Windows は組み込み winmm、macOS は macos extra の CoreMIDI を使います。ノブは上端で1回だけ反応し、パッドを離しても再度押したとは扱いません。

## プリセットと自動化

**プリセット**はすべてのページの設定を一度に取り込みます。**プリセット**
メニューから保存、読み込み、削除、エクスポート、インポートができ、起動時に
一つ適用したり、前回のセッションを自動的に復元したりできます。プリセットは
**パッケージ** — 参照するメディアを同梱した zip — としてエクスポートできる
ので、それらのファイルを持たないマシンでも開けます。

そのうえで自分で判断してくれるもの、すべて **設定** メニューから。スマート
一時停止だけが最初からオンで、それ以外はオンにするまでオフです。

| | |
| --- | --- |
| **ルール** | *「これらの条件が成り立つとき、これをする。」* 曜日、時間帯、どのアプリケーションがフォーカスされているかを組み合わせ、プリセットを適用したり、オーバーレイを隠す/表示する/閉じたり、品質を設定したりします。空欄の条件は「任意」を意味し、ルールはその条件が成り立っているあいだ繰り返しではなく、成り立ち始めたときに**一度**実行されます。条件を組み合わせられるのはここだけで、下の行はそれぞれ一種類だけを扱います。 |
| **スマート一時停止** | フルスクリーンアプリが動いているあいだ、マシンがバッテリー駆動のあいだ、あるいは指定したアプリがフォーカスされているあいだ、オーバーレイを退けます。*（デフォルトでオン、フルスクリーンのルールについて。）* |
| **アプリプロファイル** | 指定したアプリに切り替えたときにプリセットを適用します。 |
| **プリセットスケジュール** | 選んだ曜日の決まった時刻にプリセットを適用します。 |
| **テーマ** | システムに合わせるか、常にライトまたはダーク（*設定 → テーマ*）。ウィンドウは内蔵キャラクターの墨・紙・オレンジを使った FrontEngine 独自のデザインです。以前のバージョンの設定は、ライトかダークの見た目をそのまま引き継ぎます。 |
| **テーマスケジュール** | 時刻に従って昼と夜のテーマを切り替えます。 |
| **サイネージモード** | メインウィンドウを退けたまま、プリセットのリストをタイマーで巡回します。ディスプレイとして動かしっぱなしにするマシン向けです。 |
| **スクリーンセーバー** | アイドルのしきい値を超えたら、選んだ動画 / 画像 / GIF / パーティクル / ウェブページを出し、戻ってきたら下ろします。 |
| **リマインダー** | N 分ごと、または一日に一度決まった時刻に、自分で閉じるトーストとして表示します。 |
| **スリープ防止** | オーバーレイが表示されているあいだ、ディスプレイのスリープを止めます。 |
| **システムと同時に起動** | ログイン時に起動します。 |
| **スクリーンタイム** | どのアプリがどれだけの時間フォーカスされていたかを、日ごとの内訳と七日間のサマリー付きで。キーボードから離れているあいだは一時停止し、最大 60 日分を保持し、クリアするとファイル自体を削除します。 |
| **クリップボード履歴** | コピーしたものを検索し、繰り返し使うフレーズをピン留めします。クリップボードは日常的にパスワードを保持するので、別途「セッション間で保持する」にチェックを入れない限り、これは**メモリ内のみ**に保たれます。 |

## プライバシーとプラットフォームに関する注記

### マシンの外に出るもの

FrontEngine のすべては、このリストに載っていない限りローカルです。例外は四つ、
すべてオプトインです：

| Feature | Where it goes | Guard |
| --- | --- | --- |
| **テキストを読む**（ツール） | Anthropic API | 画面の文字：ツール → テキストを読むは最初にローカル OCR を使います。Windows は Windows.Media.Ocr、macOS は Vision、または実行ファイルと言語データをインストールした Tesseract を使用します。ローカル抽出はクラウドへの同意や ANTHROPIC_API_KEY を必要とせず、正常な空結果でもスクリーンショットを送信しません。翻訳と質問は、文字送信への個別の同意とキーがある場合のみ、認識済み文字を Anthropic に送ります。ローカル失敗後の画像フォールバックは、別の画像送信同意とキーを必要とします。結果にはバックエンドとエラーを表示し、同意も撤回できます。 |
| **ペットチャット** | あなたのメッセージが Anthropic の API に送られます | 同じキー、同じルール。デフォルトでオフです。 |
| **天気**（テキストソース） | 座標が Open-Meteo に送られます | キーなし、アカウントなし、身元がわかるデータなし。場所として入力したものだけです。 |
| **スマホリモート** | HTTPS | スマートフォン操作：設定 → リモート制御は HTTPS のみで、起動ごとに変わるトークンと固定アクション一覧を使います。自己署名証明書はスマートフォンに自動では信頼されません。公開証明書をエクスポートし、表示された SHA-256 指紋を照合してから端末やブラウザーの設定でインポートまたは信頼してください。秘密鍵はユーザーデータフォルダーに保存します。IP 変更、有効期限、再生成で新しい証明書の信頼が必要になる場合があります。TLS 起動失敗時も HTTP には戻しません。 |

オーディオ機能が読むのは出力の**メーター** — 単一の数値 — だけです。ただし
スペクトラムは例外で、周波数を計算するのに実際のサンプルが必要なため、システム
出力ストリームをキャプチャします。それらのサンプルはメモリ内で解析され、
ディスクに書き込まれることも、どこかに送られることも決してなく、スペクトラムを
止めた瞬間にキャプチャも止まります。

プラグイン：読み込みを有効にしてもプラグインは許可されません。plugin.json または単一ファイルの sidecar にバージョン、識別子、入口、能力を宣言し、Python import 前に承認を確認して内容のハッシュに紐付けます。コードや宣言の変更には再承認が必要です。旧プラグインは完全な信頼を明示する必要があります。設定からプラグイン承認を取り消せます。実行中のコードをアンロードするには再起動してください。Python プラグインはアプリの全権限で動き、宣言と同意は OS サンドボックスではありません。

### 画面共有のプライバシー

あなたのオーバーレイはあなたのためのものであって、共有相手のためのものでは
ありません。**設定 → 画面共有のプライバシー**から、FrontEngine は会議アプリが
開いているあいだ、それらをキャプチャから外せます：

- **オーバーレイはあなた自身の画面には残ります。** 空白になるのはキャプチャ
  されたコピーだけです。これは会議アプリやレコーダーが尊重する OS レベルの
  フラグ、Windows の `WDA_EXCLUDEFROMCAPTURE` を使います。
- **マスクは例外です。** 気を散らすものを覆うマスクは何かを覆うために存在する
  ので、あえてキャプチャの中でも見えたままにします。
- **トリガーはあなたのリストです。** Windows には信頼できる「今キャプチャ
  されているか」の API がないので、あなたが指定したウィンドウタイトルを監視
  します。これはブラウザのタブで行われる会議も捉えます。その場合、実行ファイル
  は単にブラウザだからです。

コントロールセンターには手動の*キャプチャから隠す*ボタンもあります。

> これはプライバシーであってセキュリティではありません。通常のキャプチャ経路を
> かわすだけで、机に座っている人から何かを隠すことは決してありません。

## 実行環境、プライバシー、相互運用

録画：範囲を選択し、キャプチャ開始前に出力 GIF を選びます。キャンセルでは録画を開始しません。バックグラウンドでフレームを逐次書き込み、キューは3フレームと64 MiBを上限とします。大きすぎる単一フレームは拒否します。キューが満杯ならキャプチャを省略し、経過時間を再生時間に反映します。フレームレート、時間、フレーム数の上限とカメラの小窓は維持します。停止後は非同期で完了し、成功時のみ出力先をアトミックに置換します。キャンセルや書き込み失敗時は一時ファイルを削除し、既存ファイルを保護します。

画面の文字：ツール → テキストを読むは最初にローカル OCR を使います。Windows は Windows.Media.Ocr、macOS は Vision、または実行ファイルと言語データをインストールした Tesseract を使用します。ローカル抽出はクラウドへの同意や ANTHROPIC_API_KEY を必要とせず、正常な空結果でもスクリーンショットを送信しません。翻訳と質問は、文字送信への個別の同意とキーがある場合のみ、認識済み文字を Anthropic に送ります。ローカル失敗後の画像フォールバックは、別の画像送信同意とキーを必要とします。結果にはバックエンドとエラーを表示し、同意も撤回できます。

Puppet ペット：任意の puppet extra と利用可能な Imervue runtime をインストールし、ペットページでオリジナルの Imervue .puppet v1 を選ぶかドロップします。従来の画像とスプライトパックも使えます。Puppet は Imervue のキャンバス、モーション、表情を使い、複製と終了、FrontEngine のオーバーレイ制御とプリセットに対応します。任意の .petscript.json は Imervue の既存スクリプトエンジンを使います。FrontEngine の pet.json パックは puppet ファイルではありません。未知のバージョン、危険なアーカイブパス、不正な素材は読み込み前に拒否します。

Puppet ペットは自分で散歩もします。数秒休んだあと、今の高さのまま左右どちらかへ歩行モーションで少し歩き、画面の作業領域からは出ずに、また休みます。ドラッグ、なでる、「おいで」とおもちゃ、入力中のおとなしいモード、自分で動くことを許さないモードが優先されます。

「行動」メニューの既定値「すべての動作を循環（ランダム）」では、ペットがすべての動作の中から次にすることをランダムに選びます。「床を歩く」は歩く・待つだけです。スプライトペットは歩く、待つ、座る、遊ぶ、毛づくろい、近いほうの壁まで歩いて登る、手を振る、眠る、お祝い、服を見せるの中から選び、Puppet ペットは散歩と、その場で座る・遊ぶ・毛づくろい・手を振る・お祝いの中から選びます。呼び出したペットはすぐに歩き出します。ポーズはその場で行い、そのポーズの画像がないペットは待機画像を表示します。

シーン：旧エントリーマッピング JSON、バージョン付き frontengine.scene、持ち運べる .fescene パッケージを読み込めます。PUPPET は位置、サイズ、不透明度、有限の数値パラメーターと任意のモーション、表情、スクリプトを設定できます。JSON 内のパスはシーンファイル基準です。.fescene は参照メディア、元の .puppet、任意の .petscript.json を含み、別の端末に移せます。インポートはパス、シンボリックリンク、バージョン、展開上限を検証します。FrontEngine のシーンはシーンパッケージであり、.puppet は単体の Imervue キャラクターです。

macOS：任意の macos extra は macOS 13+ と公開 PyObjC framework を使います。ScreenCaptureKit の画面／ウィンドウ／システム音声取得、マイク、Quartz のウィンドウ形状、Accessibility の配置と移動、CoreMIDI、メディアキー、F12 終了を提供します。画面収録、アクセシビリティ、マイクの権限は個別に確認します。システム設定 → プライバシーとセキュリティで許可し、要求された場合は再起動してください。他のアプリの透明度／強制最前面、Space 選択、他アプリのキャプチャからの除外は利用できません。この Windows 開発環境では macOS の権限、ハードウェア、性能を実機検証していません。 設定 → macOS の権限と能力では、各機能を利用可能、利用不可、非対応として表示し、権限やインストールの理由を説明します。

プラグイン：読み込みを有効にしてもプラグインは許可されません。plugin.json または単一ファイルの sidecar にバージョン、識別子、入口、能力を宣言し、Python import 前に承認を確認して内容のハッシュに紐付けます。コードや宣言の変更には再承認が必要です。旧プラグインは完全な信頼を明示する必要があります。設定からプラグイン承認を取り消せます。実行中のコードをアンロードするには再起動してください。Python プラグインはアプリの全権限で動き、宣言と同意は OS サンドボックスではありません。

描画：設定 → オーバーレイ描画で Auto、GPU、Software を選び、実際のバックエンドを確認できます。GPU 合成は OpenGL のテクスチャー、シェーダー、フレームバッファーで順序、変換、透明度、クリッピングを処理し、初期化失敗時は理由を表示してソフトウェアに戻ります。QPainter は CPU でラスタライズしてからアップロードする場合があり、web／video／ネイティブ widget は別ウィンドウを使う場合があります。録画は GPU フレームを CPU に読み戻す場合があります。ゼロコピーや測定済みの高速化を保証しません。 オーバーレイの再描画では、親ウィンドウの描画完了後に合成器を更新します。バックエンドやモニターの切り替え時も同じ順序です。

任意機能は以下のコマンドでインストールします。Windows OCR の WinRT 投影パッケージは Windows の通常の FrontEngine インストールに含まれ、認識用言語を Windows に追加する必要があります。Tesseract は別途実行ファイルと言語データをインストールします。puppet extra は Imervue>=1.0.90、macos extra は macOS 13+ の PyObjC framework を追加します。形式と例は docs/formats/ を参照してください。

```bash
pip install "frontengine[puppet]"
pip install "frontengine[macos]"
```

## 開発

```bash
pip install -r dev_requirements.txt
pip install -e .

python -m pytest tests/ -q          # the whole suite, headless (Qt offscreen)
```

静的チェックには pyflakes（`dev_requirements.txt` に含まれます）を使い、きれいな
ツリーは何も出力しません：

```bash
python -m pyflakes frontengine/ exe/ tests/
```

テストスイートは完全にオフスクリーンで動き、ディスプレイもサウンドカードも
カメラも要りません。外の世界に触れるものはすべて注入可能なソースを取るので、
偽物でテストできます。

- **アーキテクチャ** — [`architecture_explore.md`](../architecture_explore.md) が
  すべてのモジュール、階層構造、オーバーレイの契約、拡張点をマッピングして
  います。ページやオーバーレイを追加する前に読んでください。いくつかのもの
  （コントロールセンターのレジストリ、七つの言語辞書、七つのドキュメントツリー）
  はまとめて更新する必要があり、テストがそれを強制します。
- **貢献** — [`CONTRIBUTING.md`](../CONTRIBUTING.md) を参照。プルリクエストごと
  に一機能、すべての CI チェックがグリーン。
- **Windows 実行ファイルのビルド** — `python exe/build_exe.py`
  （Nuitka。単一ファイルにするには `--onefile` を追加）。
  既定ではすべての CPU コアでコンパイルします。`--jobs N` で並列ジョブ数を制限（メモリ節約）、`--jobs -N` で N コアを空けておきます。
- **ドキュメント** — Sphinx ソースは `docs/` にあり、七つすべての言語で
  [Read the Docs](https://frontengine.readthedocs.io/en/latest/) に公開されて
  います。

## 継続的インテグレーションとリリース

作業は `feature → dev → main` と流れ、公開するのは最後のステップだけです：

```
feat/xyz  ──PR──►  dev  ──PR──►  main
                    │              │
              CI, no release   CI + release
```

| Workflow | Trigger | Purpose |
| --- | --- | --- |
| `CI` (`ci.yml`) | `main` または `dev` へのプッシュ / PR、手動ディスパッチ、または `Nightly` からの呼び出し | コンパイルし、ユニットテストを実行し、その後*そのチェックアウト*から wheel をビルドし、インストールしてアプリを起動 — Python 3.11 / 3.12、Windows で |
| `Nightly` (`nightly.yml`) | 毎日の cron、手動ディスパッチ | `CI` を呼び出します。スケジュールがここにあるのは意図的です。GitHub は cron を含むワークフローを約 60 日間の非アクティブののちに無効化するため、そうでなければ PR チェックも道連れになってしまうからです |
| `Release` (`release.yml`) | **`dev` からの**プルリクエストが `main` にマージされる、または手動ディスパッチ | バージョンを上げ、`[skip ci]` を付けてコミットバックし、`stable.toml` → `pyproject.toml` を入れ替え、sdist + wheel をビルドし、`frontengine` として PyPI にアップロードし、`v<version>` のタグを付けた GitHub リリースを作成し、`dev` を早送りします |

公開が起きるのは **`dev` が `main` にマージされたときだけ** です。機能は
バージョンを発行せずに `dev` に着地し、リリースは意図的な `dev → main` の
プルリクエストです。誤って `main` に向けた機能 PR もマージはされますが公開は
されません。失敗の方向はリリースの欠落であって、望まないリリースではありません。

パッチ部分は自動的に上がります。マイナーまたはメジャーリリースには、
*Actions → Release → Run workflow* を実行して部分を選びます。その経路は、
新しいマージを必要とせずに失敗した公開を再実行することもできます。

バージョンは二つのファイルに存在します。`pyproject.toml` は dev パッケージ
（`frontengine_dev`）、`stable.toml` は公開されるもの（`frontengine`）です。

リポジトリシークレットが一つ必要です。`PYPI_API_TOKEN`、`frontengine` プロ
ジェクトにスコープされた PyPI トークンです。ワークフローは twine のユーザー名
として `__token__` を使うので、トークンそのものだけを保存すれば済みます。

ペットのセーブデータは別のファイル名で書き出してください。設定、ホーム、バックアップ、一時ファイル、ロックファイルの予約名と、リンク先のファイルへの書き出しは拒否されます。

画像 → 画像を比較は、共通のズーム／移動ビューで二枚を並列、透明重ね合わせ、スライド境界、RGB 絶対差で表示します。拡縮せず左上または中心に合わせるか、縦横比を保って B を A に収めます。ホイールは両方をズームし、スライダーは B の透明度または境界を調整します。透明部分と余白は白背景で比較し、差分の黒は RGB が同一です。アニメーションは最初のフレームのみ使用します。読み込み、整列、差分計算は背景で一件ずつ行い、最新の選択のみ適用します。透明度／境界は画像キャッシュを再利用します。上限は各ファイル 64 MiB、一辺 8,192 ピクセル、各画像／キャンバス 16,777,216 ピクセルです。読み込み失敗時は前の二枚を保持し、終了時は画像を解放して遅い結果を無視します。

自由配置では活動、アイテム、モード内の進行を維持しますが、コインは獲得も消費もしません。価格、報酬、完了通知もこのルールに従います。古い自由配置のセーブを読み込むと残高はゼロになり、アイテムと取引履歴は保持されます。通常の家の残高は変わりません。

住民の誕生日は、入居からゲーム内で7日ごとの記念期間に1回だけ祝います。同じ記念期間に日付が変わったりセーブを開き直したりしても、気分の報酬や受信箱の通知は繰り返されません。

表示中の住民の名前は、家園画面とデスクトップバーの左右端でも画面内に収まります。長い名前は省略記号で短縮され、名前の背景も文字の位置に合わせて表示されます。

活動の吹き出しはデスクトップバーの左右端でも画面内に収まり、幅を超える文字は省略記号で短縮されます。画面外の住民の吹き出しは表示せず、集中・会議モードに切り替えると表示中の吹き出しもすぐに隠れます。

睡眠の指示は、自分のベッドがあるエリアへ戻った後も続きます。元気が残っていても散歩には切り替わりません。停止または別の指示で移動を中止します。移動中にベッドを収納した場合は、到着後に床で昼寝します。

別のエリアにいる住民を選ぶと、家の全体表示がその住民のエリアに切り替わります。同じエリアの住民を選ぶ場合や選択を解除する場合は、現在の配置画面を維持します。

退去時にペットのプロフィールを保存できない場合、住民の選択は保持され、書き込みが可能になった後にそのまま再試行できます。保存済みのペットや新しいペットの入居が拒否された場合も現在の選択を保持し、入居に成功した場合のみ新しい住民を選択します。

新しいペットのプロフィールを保存できない場合、エラーを表示し、住民は追加しません。書き込みが可能になったら「新しいペット」で再試行できます。初めて家を作るときに失敗しても空の家は操作でき、再試行で初期セットが重複して付与されることはありません。

表示言語を切り替えると、画質、測定モード、テキスト読み取り操作、カメラ枠、スペクトラム表示の選択肢も更新されます。選択済みの値は保持され、言語の変更によってツールの設定が変わることはありません。

表示言語を切り替えると、3D エディターの変形ツール、軸、座標空間、投影、ライトの種類の選択肢も更新されます。選択値、シーンの内容、元に戻す履歴は変わりません。

シーンスクリプトとメディアのサブタブ名も表示言語に合わせて更新されます。選択中のタブやページはそのまま維持され、シーンの内容と元に戻す履歴も保持されます。

表示言語を切り替えると、対象モニターの選択肢と最近使ったファイルの案内も更新されます。対象モニター、ファイル名とパス、選択値は変わりません。最近使ったファイル一覧を再読み込みした後も言語を切り替えられます。

3D エディターの自動再生時間と親なしの表示も、表示言語に合わせて更新されます。別のオブジェクトを選択して戻った場合も、再生時間の値と親子関係は変わりません。

内蔵キャラクターを追加すると、キャラクターと服の生成および検証付きインストールの進捗が表示されます。割合は完了した手順を示し、残り時間ではありません。成功または失敗すると進捗バーが消えます。クローゼットを閉じると未完了の処理がキャンセルされます。

ペットの操作結果は実行ボタンの上に表示され、キーボードフォーカスの近くで確認できます。狭いウィンドウではセクション見出しと詳細ボタンが折り返されます。ペットと操作の欄は読みやすい最小幅を保ち、必要に応じてラベルの下に移動します。選択、入力値、コマンドは保持されます。

ペットのカスタマイズ欄は、Qt のアクセシビリティ機能を通じて表示ラベルを提供します。好き・嫌いなおやつ、サイズ、速度、音量、行動、おしゃべり、アニメーションの大きさの名前は、画面の言語に合わせて更新されます。

衣装とペット写真の欄は、Qt のアクセシビリティ機能を通じて表示ラベルを提供します。衣装の部位、保存したコーデ、ポーズ、ポーズの時刻などの名前は、下書きや写真を変更せずに画面の言語に合わせて更新されます。

ペット写真の撮影時のポーズ項目は画面の言語に合わせて更新され、選択中のポーズ、時刻、写真を保持します。
