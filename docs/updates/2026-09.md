## U-20260923-01 · 2026-09-23 · FrontEngine.log moves out of the working directory · #done #logging

- **What** (workspace item X-6): `frontengine/utils/logging/loggin_instance.py` opened `FrontEngine.log` in the working directory at import (falling back to the home directory, then to no file). JEditor and PyBreeze embed FrontEngine, so every process that imported it left a `FrontEngine.log` wherever it started; `D:\Codes\JEDITOR` and the workspace root had collected them. The handler also rotated inside `emit()` at 1 GiB, which fails on Windows while another process holds the file.
- **Now**, the same design as AutoControlGUI (`5714a59`) and JEditor: `$FRONTENGINE_LOG_FILE` or `~/.frontengine/logs/FrontEngine.log`; the package handler is built with `delay=True`, so importing writes nothing; append mode with the process id on each line; rotation to `.1` past 10 MiB only when a process opens the file; UTF-8 with `errors="backslashreplace"`; an unopenable path falls back to `os.devnull` with one `RuntimeWarning` (the old candidate chain existed so a read-only launch directory could not stop the app; that guarantee holds). `_build_file_handler` and `LOG_FILE_NAME` are gone; nothing else used them.
- **Tests**: `tests/unit_test/test_log_location.py` (9, same cases as JEditor's): home default, environment override, loading the module alone in a fresh interpreter leaves the cwd empty, first record creates the directory and later handlers append, text outside cp950 and a lone surrogate survive, an unopenable path only warns, the package handler's path, mode and encoding. `py -m pytest tests/ -q` 1184 passed; `pyflakes frontengine/ exe/ tests/` silent.
- **Branch**: `dev` was an ancestor of `main` (three main-only doc commits: `289aa7c`, `54a2028`, `2adaddb`); it was fast-forwarded to `main` before this commit, as `CLAUDE.md` describes for a release that could not move `dev`.
